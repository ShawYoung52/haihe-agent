# 叫应功能交接说明（乙方 → 甲方）

> 本文档说明"应急响应叫应功能"已完成的建设内容，以及甲方需要配合提供的配置与部署事项。

## 一、功能说明

**叫应机制**：当海河流域应急响应等级发生变化（Ⅰ-Ⅳ级）时，系统自动创建"叫应任务"。值班人员**人工确认**后，系统自动通过微信向受影响单位对应的微信群发送**叫应话术 + 天河报告文件**（docx/pdf），并记录逐群发送台账，形成完整闭环。

```
应急响应等级变化 → 创建叫应任务 → 值班人员人工确认 → 微信自动发送(话术+报告) → 记录台账
```

**系统能力**（已开发完成并测试通过）：
- 应急响应等级变化自动建任务（同等级持续不重复）
- 值班人工确认 API（前端页面由前端团队后续实现）
- 后台异步发送，不阻塞 5 分钟降雨监测主流程
- 逐群发送台账记录（成功/失败/原因）
- 报告缺失或群未配置时任务挂起，配置齐后自动补发

## 二、甲方需要提供 / 配合事项

### 1. 群映射配置（核心待办）

受影响的单位（城市）需要映射到具体的微信群名。请提供以下对应关系：

| 受影响城市/区县 | 对应的微信群名 |
|---|---|
| （请填写，如：天津市） | （请填写，如：天津市防汛值班群） |
| （请填写，如：廊坊市） | （请填写，如：廊坊防汛值班群） |
| ... | ... |

> 说明：群名须与微信中实际群名完全一致；一个城市可对应多个群。未配置的城市，其叫应任务会挂起等待配置，不会报错。

### 2. 部署环境变量（调度器侧）

需要提供微信网关的访问地址与 token，用于调度器调用微信发送：

| 环境变量 | 说明 | 示例 |
|---|---|---|
| `WECHAT_GATEWAY_URL` | 微信网关地址 | `http://<网关服务器IP>:18080` |
| `WECHAT_GATEWAY_TOKEN` | 微信网关鉴权 token | （由网关侧生成） |

### 3. 微信网关白名单（网关侧）

请配合在微信网关服务器确认/补充：
- **IP 白名单**：调度器（Linux 服务器）的 IP 加入网关 `ALLOWED_CLIENT_IPS`，否则请求被拒绝（403）
- **群白名单**：上述群映射中的群名加入网关 `ALLOWED_TARGETS`，否则微信发送被拒绝

### 4. 数据库建表

甲方 DBA 在内网 PostgreSQL 执行建表脚本：
`scripts/create_call_respond_tables.sql`（幂等，可重复执行）

建两张表：`qy_call_respond_task`（叫应任务）、`qy_call_respond_send_log`（发送日志）。

## 三、部署流程（甲方/运维）

1. **建表**：执行 `scripts/create_call_respond_tables.sql`
2. **更新代码**：`git pull origin main`
3. **配置环境变量**：调度器进程设置 `WECHAT_GATEWAY_URL`、`WECHAT_GATEWAY_TOKEN`
4. **配置群映射**：编辑根目录 `call_respond_config.json` 的 `groups` 字段（见附）
5. **网关侧**：确认 IP 白名单、群白名单
6. **重启调度服务**：`systemctl restart station-process-min`
7. **验证**：见第四节

## 四、验收/验证清单

- [ ] 调用确认接口后，受影响微信群收到**话术 + 报告文件**（docx 下载 / pdf 查看）
- [ ] `qy_call_respond_send_log` 表逐群记录发送成功
- [ ] 报告缺失时任务挂起，报告生成后自动补发
- [ ] 群未配置时任务挂起不报错，配置后自动补发
- [ ] 微信发送失败时任务标记失败（可重试），不误报成功
- [ ] 整个发送过程不阻塞 5 分钟降雨监测主流程

## 附：`call_respond_config.json` 配置示例

```json
{
  "template": "【叫应】{city} 已启动 {level} 级应急响应，请各单位迅速响应，报告见附件。",
  "groups": {
    "天津市": ["天津市防汛值班群"],
    "廊坊市": ["廊坊防汛值班群"]
  }
}
```

- `template`：话术模板，`{city}` 和 `{level}` 为占位符（自动替换为受影响城市与应急等级）
- `groups`：城市 → 微信群名列表（**需甲方提供后填写**）

## 五、API 一览（供前端团队对接）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/tool/call-respond/tasks?status=pending` | 查询叫应任务列表（可按状态筛选） |
| POST | `/tool/call-respond/{id}/confirm` | 值班人工确认（body: `{"confirm_person":"张三"}`） |
| GET | `/tool/call-respond/{id}/logs` | 查询某任务的逐群发送日志 |
| POST | `/tool/call-respond/{id}/retry` | 手动补发（重试失败群） |
