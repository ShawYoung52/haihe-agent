# 问答智能体 HTTP 接口对接文档（给天河小程序）

## 接口列表

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/v1/qa/ask` | 问答 |
| GET | `/api/v1/qa/files/{session_id}/{file_id}` | 取图表图片 |

基础路径：`http://${QA_API_BASE}`（部署时替换为实际地址与端口）。

---

## POST /api/v1/qa/ask

### 请求

```json
{
  "question": "海河流域明天天气怎么样？",
  "conversation_id": "c8f3a1e2-1234-5678-9abc-def012345678",
  "include_reasoning": true,
  "include_gis": true
}
```

| 字段 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| `question` | string | **是** | — | 用户问题，非空，最长 2000 字 |
| `conversation_id` | string | 否 | — | 多轮会话 id（UUID 格式）。不传 = 单轮，不带上下文。首次请求不传，服务端会在响应中返回新 id，后续带上即可延续对话 |
| `include_reasoning` | bool | 否 | `true` | 是否返回思考过程（推理步骤文字） |
| `include_gis` | bool | 否 | `true` | 是否返回 GIS 图层数据（河网 GeoJSON，可达数 MB） |

### 响应

**成功（200）：**

```json
{
  "code": 200,
  "data": {
    "answer": "海河流域明天多云，局地小雨，降雨量 5-15 毫米……",
    "conversation_id": "c8f3a1e2-1234-5678-9abc-def012345678",
    "images": [
      {
        "name": "rain_dist",
        "url": "/api/v1/qa/files/aaaaaaaa-bbbb-cccc-dddd-eeeeeeeeeeee/ffffffff-gggg-hhhh-iiii-jjjjjjjjjjjj.png",
        "mime": "image/png"
      }
    ],
    "gis": [
      {
        "type": "gis_linkage",
        "schema_version": "v2",
        "scene": "river_downstream",
        "query": "蓟运河下游有哪些",
        "map": { "geojson": {...}, "layers": [...] },
        "panel": { "tables": [...] }
      }
    ],
    "reasoning": [
      "🔍 理解问题：用户询问海河流域明天天气……",
      "📡 查询数据：正在从 ECMWF 预报中提取……"
    ],
    "elapsed_seconds": 12.3
  },
  "message": "success"
}
```

- `conversation_id` 始终回传，首次请求可据此保存会话
- `answer` 为空时返回兜底文案，不会返回空串
- `images` 里的 URL 是相对路径，拼接基础地址后直接用作 `<image>` 的 `src`
- `gis` 里的 GeoJSON 可能**较大**（数 MB），建议按需请求（设置 `include_gis: false`）
- `reasoning` 为字符串数组，每条对应一个思考步骤

**错误：**

| 状态码 | 说明 |
|---|---|
| 400 | 参数错误（question 为空/超长、conversation_id 格式非法） |
| 429 | 并发请求过多，稍后重试 |
| 500 | 服务端异常 |
| 503 | 问答服务尚未初始化完成，稍后重试 |
| 504 | 问答处理超时（默认 180 秒） |

## GET /api/v1/qa/files/{session_id}/{file_id}

返回图片二进制。可直接用作 `<image src>`。

| 状态码 | 说明 |
|---|---|
| 200 | 图片二进制（Content-Type 为对应 MIME） |
| 400 | session_id 或 file_id 格式非法 |
| 404 | 图片不存在或已过期（TTL 默认 30 分钟） |

图片 URL 从 `POST /qa/ask` 响应的 `images[].url` 字段获取，不要自行拼接。

## 多轮对话

```
首次请求：
  POST /api/v1/qa/ask  { "question": "海河流域明天天气？" }
  → { "data": { "conversation_id": "abc-123", "answer": "……" } }

后续追问：
  POST /api/v1/qa/ask  { "question": "那后天呢？", "conversation_id": "abc-123" }
  → 服务端自动带上之前的历史上下文
```

约束：
- conversation_id 格式必须是标准 UUID（`xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx`）
- 会话空闲超过 1 小时自动过期（`QA_API_CONVERSATION_TTL_SECONDS` 可调）
- 历史最多保留最近 **10 轮**问答（`QA_API_MAX_HISTORY_TURNS` 可调）
- 服务重启后所有会话上下文丢失，客户端需重新开始对话

## curl 示例

```bash
# 单轮问答
curl -X POST http://${QA_API_BASE}/api/v1/qa/ask \
  -H "Content-Type: application/json" \
  -d '{"question":"海河流域明天天气怎么样？"}'

# 多轮（带上上一轮的 conversation_id）
curl -X POST http://${QA_API_BASE}/api/v1/qa/ask \
  -H "Content-Type: application/json" \
  -d '{"question":"那后天呢？","conversation_id":"abc-123"}'

# 只要答案，不要图表和 GIS
curl -X POST http://${QA_API_BASE}/api/v1/qa/ask \
  -H "Content-Type: application/json" \
  -d '{"question":"明天会下雨吗？","include_reasoning":false,"include_gis":false}'

# 取图片
curl http://${QA_API_BASE}/api/v1/qa/files/{session_id}/{file_id} -o chart.png
```

## 性能优化说明

为提升响应速度，已加入两层缓存：

**1. 接口响应缓存（`QA_API_RESPONSE_CACHE_TTL`，默认 300 秒）**
- 相同的 `question`（含 `include_reasoning` / `include_gis` 开关）在 5 分钟内重复请求，直接返回上次结果，不重新跑完整问答流程
- **多轮请求（带 `conversation_id`）不缓存**，保证上下文正确
- 适合"今天天气""明天天气""梅江会展中心明日天气"这类高频查询

**2. 数据查询缓存（`ROLLING_FORECAST_CACHE_TTL`，默认 600 秒）**
- 滚动预报数据查询（同一起报时次 + 坐标 + 时段）在 10 分钟内重复会命中缓存，避免重复打内网数据接口
- 该内网接口实测可达几十秒，是"数据查询慢"的主要来源，缓存后秒回

**3. 简单天气规则路由**
- "今天/明天/后天/周末 + 天气"这类明确高频问题直接路由到天气工具，跳过 planner 大模型智能路由（省 5-10 秒）
- 带具体地点（如"梅江会展中心明日天气"）走点位决策天气；不带地点走天津滚动预报
- 流域/河系问题（海河流域、X河）和决策类问题（适合/能否/去/活动）不命中，仍走 planner 智能路由

**4. POI 检索缓存（`POI_SEARCH_CACHE_TTL`，默认 3600 秒）**
- POI 检索（"梅江会展中心""天津站"等地点搜索）相同关键词在 1 小时内缓存 ES 查询结果
- POI 数据（地点名称/经纬度/地址）是静态的，缓存安全可靠

**缓存复用场景**：多个用户问同一个问题（如"梅江会展中心明日天气"），响应缓存直接命中 + 数据查询缓存命中 + POI 缓存命中，无需任何内网查询。

## 注意事项

1. **无鉴权**：当前接口无认证机制，建议在部署时通过 IP 白名单限制只有天河后端服务器可访问
2. **超时**：单次问答最长等待 180 秒（可调），超时返回 504。复杂问题（需要多次工具调用 + 长答案）建议在客户端给用户提示"正在分析中"
3. **图片有效期**：图表图片默认 30 分钟后自动清理。如需长期保存，客户端应自行转存
4. **内网**：服务仅供内网访问，不可暴露到公网
5. **并发**：当前最大并发数 4（可调），超出排队等待
6. **缓存时效**：天气预报数据短时间稳定，接口响应缓存 5 分钟、数据查询缓存 10 分钟。若有强实时性要求（如临近预警），可调小 `QA_API_RESPONSE_CACHE_TTL` / `ROLLING_FORECAST_CACHE_TTL`
