# Weather Agent 问答 API 内网后端接入说明

## 1. 适用范围

本文供受控内网中的后端服务调用 Weather Agent 问答能力。调用方可以通过同一个接口访问已经配置的 Fixed QA（固定问答）和普通问答能力；服务端仍会按自身路由规则处理问题。

- 接口路径：`/api/qa`
- 调用方式：HTTP `POST`
- 数据格式：UTF-8 JSON
- 调用模式：非流式
- 当前鉴权：接口自身暂未校验调用方身份，仅限受控内网使用，不得直接暴露到互联网

当前项目配置的服务根地址为：

```text
http://10.226.188.156:8001
```

完整问答接口地址为：

```text
http://10.226.188.156:8001/api/qa
```

如果后续部署地址发生变化，应同步更新本文及调用方配置。

> 如果后续在接口前增加统一网关、访问令牌或签名校验，应以网关另行提供的鉴权说明为准。当前调用示例不虚构尚未实现的鉴权请求头。

## 2. 接口概览

```http
POST http://10.226.188.156:8001/api/qa
Content-Type: application/json; charset=utf-8
```

建议调用方配置：

- 连接超时：5 秒
- 普通问答响应超时：120 秒
- 字符编码：UTF-8
- 自动重试：仅限连接失败或明确的临时服务端错误，最多重试 2 次

上述 120 秒是 Fixed QA 和普通问答的接入建议，不是服务端强制值。如果通过同一问答入口触发报告或长图等耗时操作，应另行确认更长的超时时间，且不要盲目自动重试生成类请求。

## 3. 请求参数

请求体是一个 JSON 对象：


| 字段         | 类型               | 必填  | 说明                        |
| ---------- | ---------------- | --- | ------------------------- |
| `question` | `string`         | 是   | 当前问题。去除首尾空白后不得为空。         |
| `history`  | `array` 或 `null` | 否   | 之前的对话历史。单轮调用建议传空数组 `[]`。  |
| `stream`   | `boolean`        | 是   | 本文只使用非流式调用，必须显式传 `false`。 |




### 3.1 `history` 数据结构

`history` 中每一项包含：


| 字段        | 类型       | 说明                                        |
| --------- | -------- | ----------------------------------------- |
| `role`    | `string` | 对外只使用 `user` 或 `assistant`。其他角色当前会被服务端忽略。 |
| `content` | `string` | 该轮完整文本。                                   |


历史消息应按实际发生时间从早到晚排列。`question` 是当前新问题，不要再把它重复放进 `history`。

### 3.2 为什么不能省略 `stream`

服务端当前将 `stream` 的默认值设为 `true`。调用方如果省略该字段，返回类型会变成流式响应，与本文约定的普通 JSON 不同。因此，所有请求都必须明确包含：

```json
{
  "stream": false
}
```



## 4. 最小请求与响应



### 4.1 单轮 Fixed QA 请求

下面的问题已经存在于当前 Fixed QA 目录中：

```json
{
  "question": "今天雨下了多长时间",
  "history": [],
  "stream": false
}
```



### 4.2 成功响应

返回格式示例，正文以实际调用时的数据和服务状态为准：

```json
{
  "answer": "服务端根据调用时的数据生成的完整回答正文"
}
```

调用方应读取顶层 `answer` 字段。`answer` 是完整 UTF-8 字符串，可能包含中文标点、换行、Markdown 标题、列表或表格；不要按固定句子、固定行数或固定分隔符解析。

服务端在特定调试配置或特殊操作路由下可能返回额外顶层字段。调用方应采用向前兼容的 JSON 解析方式：读取所需的 `answer`，同时容忍未知字段，不要因为多出字段就判定响应失败。

## 5. Fixed QA 调用说明

Fixed QA 在普通问答之前执行。只有问题命中 Fixed QA 目录时，服务端才会走对应的固定模板、知识库强制检索或已批准的外部处理路径。

### 5.1 匹配规则

服务端会对问题做以下轻量规范化：

- Unicode NFKC 规范化；
- 合并连续空白；
- 删除首尾空白；
- 删除句末标点。

除此之外仍然是整句精确匹配，不做包含匹配、同义词替换或模糊语义匹配。

例如：


| 输入问题         | 是否命中同一个 Fixed QA | 原因               |
| ------------ | ---------------- | ---------------- |
| `今天雨下了多长时间`  | 是                | 与目录问题一致。         |
| `今天雨下了多长时间？` | 是                | 句末标点会被移除。        |
| `今天雨下了多长时间`  | 是                | 首尾空白会被移除。        |
| `今天的雨下了多久`   | 否                | 这是不同句式，不做同义改写匹配。 |


未命中 Fixed QA 不代表接口失败。该问题会继续进入现有普通问答或操作路由。

### 5.2 当前可用于联调的真实问题示例

以下问题均来自当前已启用的 Fixed QA 目录：

- `今天雨下了多长时间`
- `全市现在下了多少雨`
- `市区现在气温和风的实况`
- `暴雨天气的防范建议`

其中实时观测和降雨类回答会随调用时的数据变化；知识类回答也可能随知识库内容和模型状态变化。调用方只能依赖响应外层结构，不应把某次正文当作永久固定值。

## 6. 普通问答和多轮对话

接口没有限制为只能调用 Fixed QA。未命中 Fixed QA 的问题会继续由现有问答链路处理。

### 6.1 普通问答请求

```json
{
  "question": "请解释什么是强对流天气",
  "history": [],
  "stream": false
}
```

成功响应仍使用相同外层结构：

```json
{
  "answer": "服务端生成的完整回答正文"
}
```



### 6.2 多轮对话请求

```json
{
  "question": "它可能带来哪些灾害？",
  "history": [
    {
      "role": "user",
      "content": "什么是强对流天气？"
    },
    {
      "role": "assistant",
      "content": "强对流天气通常伴随短时强降水、雷暴大风或冰雹等现象。"
    }
  ],
  "stream": false
}
```

实际接入时，`assistant.content` 应使用上一轮接口返回的完整 `answer` 原文。

## 7. 调用示例

以下示例均直接使用当前配置的完整问答接口地址。

### 7.1 cURL

```bash
curl --silent --show-error \
  --connect-timeout 5 \
  --max-time 120 \
  --request POST \
  --header 'Content-Type: application/json; charset=utf-8' \
  --data-raw '{
    "question": "今天雨下了多长时间",
    "history": [],
    "stream": false
  }' \
  'http://10.226.188.156:8001/api/qa'
```



### 7.2 Python（`requests`）

```python
import requests


payload = {
    "question": "今天雨下了多长时间",
    "history": [],
    "stream": False,
}

response = requests.post(
    "http://10.226.188.156:8001/api/qa",
    json=payload,
    timeout=(5, 120),
)
response.raise_for_status()

data = response.json()
answer = data.get("answer")
if not isinstance(answer, str):
    raise ValueError(f"响应缺少字符串字段 answer: {data}")

print(answer)
```



## 8. 响应解析要求

调用方应遵循以下规则：

1. 先判断 HTTP 状态码是否为 `2xx`。
2. 成功状态下，将响应体解析为 JSON 对象。
3. 校验 `answer` 存在且类型为字符串。
4. 原样保留 `answer` 中的换行和 Markdown；是否渲染 Markdown 由调用方自行决定。
5. 容忍额外顶层字段，避免服务端增加可选字段时导致调用失败。
6. 不要通过某段具体中文正文判断是否命中 Fixed QA；Fixed QA 的内部路由信息不是当前公开响应契约。



## 9. 错误与降级处理



### 9.1 空问题：HTTP 400

当 `question` 去除首尾空白后为空时：

```json
{
  "detail": "question is empty"
}
```

调用方应修正请求，不要自动重试。

### 9.2 请求结构错误：HTTP 422

以下情况通常返回 FastAPI 的 HTTP `422` 校验错误：

- 缺少 `question`；
- 字段类型不符合要求；
- `history` 项缺少 `role` 或 `content`；
- 请求体不是合法 JSON。

`422` 返回中的 `detail` 结构可能随 FastAPI/Pydantic 版本变化。调用方应记录 HTTP 状态和脱敏后的错误详情，不要依赖某一条固定英文错误文本。

### 9.3 服务端错误：HTTP 5xx

未处理的服务端异常可能返回 HTTP `5xx`。调用方可以对连接失败、`502`、`503` 或 `504` 做有限重试，例如最多 2 次并使用递增等待；不要无限重试。

如果问题可能触发报告或长图生成，自动重试可能造成重复生成。此类请求应先查询任务状态或由业务方人工确认。

### 9.4 HTTP 200 但返回降级正文

部分模型、知识库或数据源故障会以 HTTP `200` 返回稳定的中文降级提示，例如：

```json
{
  "answer": "智能体服务暂时不可用，请稍后重试。"
}
```

因此，HTTP `200` 只表示接口成功返回了问答结果，不保证实时数据源或模型本次调用完全正常。调用方仍应读取并展示 `answer`，不要把业务降级文本当作 JSON 解析失败，也不要对所有降级正文自动重试。

## 11. 最小联调结论

如果下面请求能够得到 HTTP `200`，响应体是合法 JSON，且包含字符串字段 `answer`，即可确认最基本的非流式问答接入成功：

```json
{
  "question": "今天雨下了多长时间",
  "history": [],
  "stream": false
}
```

Fixed QA 的实时正文由服务端数据源、知识库和运行状态决定，调用方只需遵守本文约定的请求字段、非流式标记和响应解析方式。
