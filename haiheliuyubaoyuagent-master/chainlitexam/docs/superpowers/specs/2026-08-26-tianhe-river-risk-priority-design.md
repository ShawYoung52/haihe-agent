# 天河新目录与流域重点问题接入设计

日期：2026-08-26  
状态：实现及离线回归已完成；独立最终审查待执行，完整依赖环境复测和内网联调待完成

执行结论见[56题验收记录](../2026-08-27-priority-acceptance.md)。第2.3节的河系能力复用仅在今天/明天/后天/今晚/未来N自然日单一窗口内由统一MCP入口调用既有核心实现；周/周末、明确日期、其他日内/小时或混合时段以及未定时问法保留原Planner/河系处理，新核心不支持时明确invalid_request、不改成今天。统一入口内裸河名先查全量河道，缓冲使用geography真实米制距离，新区域风险no_data表示不可用。原提案与执行有差异时，以验收记录中的控制器裁定及代价说明为准。

## 1. 背景与目标

本次交付包含两组需求：

1. 将甲方明确提供的 51 个天河问题接入现有问答智能体，保持天河任务边界，不把普通天气问题误送天河。
2. 优先完成需求文档中标黄的 5 个问题：
   - 明天泃河有雨吗？
   - 今天晚上滦河有雨吗？
   - 今天蓟州可能有哪些风险？
   - 未来三天于桥水库降雨预报？
   - 盘山景区未来两天天气？

设计目标是提高路由确定性和业务正确性，不开启快速路径，不改变登录、权限、消息编排以及既有问答的回答格式。

## 2. 已确认的业务口径

### 2.1 天河任务边界

- 本次新增的 51 个问题全部纳入天河验收目录；此前已经接入并验收的 03/04/05 天河问题继续保留，新增目录不得造成回归。
- 匹配时只归一化首尾空白、句内多余空白及中英文问号等标点差异，不进行宽泛语义扩展。
- 调用 `query_tianhe_fixed_qa` 时必须传递用户问题原文，不得改写、概括或补充。
- 天河服务不可用时直接说明服务不可用，不由本地智能体替代回答或补造数据。
- 普通预报、预警过程实况和其他非目录问题继续走原有本地工具。例如“未来三天天气怎么样”不得调用天河；“高温预警期间最高会到多少度”继续查询本地生效预警正文。

### 2.2 具体河流降雨口径

- “泃河”等具体河流从 PostgreSQL 表 `haihe_river_directed_full_v6` 获取真实河道几何。
- 将河道几何转换为两侧各 5 公里的沿河缓冲区，再与预报降雨栅格叠加计算。
- 回答明确标注统计范围为“河道两侧约 5 公里沿线范围”。
- 结果可包含是否有雨、沿河平均雨量、最大雨量、主要降雨时段和真实数据来源。
- 河流降雨工具没有提供气温、风力、湿度等字段时，不得补写这些要素。

### 2.3 河系、区域风险、水库和景区口径

- 明确的九分区河系问题继续使用现有 `get_river_system_rainfall_forecast`。
- 输入既可能是河系名也可能是具体河流名时，先查 `haihe_river_directed_full_v6`；命中具体河流则按沿河 5 公里范围统计，否则再按已知河系匹配。
- “今天蓟州可能有哪些风险”一次汇总地质灾害、山洪和中小河流风险，不依赖模型自行发起三次松散查询。
- 风险服务有效返回无风险时写“无风险”；服务失败时明确说明查询失败，禁止把缺数伪装成无风险，也不输出“暂无对应时次风险资料”。
- 于桥水库和盘山景区复用现有 POI 决策天气能力，通过确定性的工具约束保证命中。
- 注意事项只允许由实际返回的降雨、雷电、风力、能见度、高温和灾害风险触发。数据中没有的现象不得写入回答。

### 2.4 时间窗口

- “明天”：服务器所在时区的下一自然日 00:00—24:00。
- “今天晚上”：当天 18:00—24:00；若提问时已过 18:00，则从当前可用预报时次起算至当天结束。
- “未来三天”“未来两天”：按连续自然日分别查询和统计，不把整个时段总量重复写入每一天。
- 所有相对日期在请求时动态解析，不在代码或提示词中固定具体日期。

## 3. 总体方案

采用“确定性工具边界 + 现有回答流水线”的方案。

`ENABLE_FAST_PATHS` 始终保持 `False`。本次所谓确定性路由仅发生在工具选择和参数约束层，问题仍经过现有 Chainlit 思考、工具执行、评估和最终回答流程，不引入新的快速回答分支。

路由优先级如下：

1. 天河 51 题精确目录。
2. 具体河流、河系、区域综合风险、水库和景区规则。
3. 现有通用规划流程。

这样可以防止天河目录被本地简单天气路由抢占，也可以防止具体河流问题被错误送到天津滚动预报。

## 4. 组件设计

### 4.1 天河目录路由

在 Chainlit 编排层维护单一、可测试的新增天河目录常量和匹配函数，避免提示词、路由器和测试各自维护不同列表；此前已经接入的 03/04/05 目录规则继续作为兼容层保留。

匹配结果进入已有天河硬边界：

```text
用户原文
  → 轻量规范化后优先匹配新增 51 题目录
  → 命中：仅允许 query_tianhe_fixed_qa
  → 工具参数 query 使用用户原文
  → 返回天河结果或明确的服务不可用提示
```

目录之外的问题不得因为包含“暴雨”“高温”“今天”等关键词就调用天河。

### 4.2 具体河流沿线降雨工具

新增一个具体河流沿线降雨核心能力，职责包括：

1. 从配置读取 `river_table_full`，默认值为 `haihe_river_directed_full_v6`。
2. 使用参数化 SQL 按 `river_name` 和 `src_name` 查找河流，优先精确匹配，再进行受控包含匹配。
3. 合并同名河段并修复无效几何。
4. 在米制坐标系中构造 5 公里缓冲区，再转换到降雨栅格坐标系。
5. 复用现有滚动预报/EC 降雨栅格选择逻辑和降雨统计逻辑。
6. 按自然日或指定时段返回独立统计结果。

建议工具输入：

- `river_name`
- `start_time`
- `forecast_hours` 或明确的 `end_time`
- 内部默认 `buffer_km=5.0`，不交由模型随意修改

建议返回字段：

- `river_name`
- `matched_river_name`
- `scope_description`
- `start_time`、`end_time`
- `average_rainfall_mm`、`max_rainfall_mm`、`min_rainfall_mm`
- `has_rain`
- `data_source`
- `valid_count`

未找到河流、数据库失败、预报文件不可用和有效栅格像元为零必须分别返回可识别的错误状态，不得统一转换成“无雨”。

### 4.3 河流与河系识别

扩展当前工具选择规则，使“明天泃河有雨吗”“今天晚上滦河有雨吗”这类“时间词在前、河名在中、河后接有雨”的句式能被识别。

识别后按以下顺序选择：

1. 查询具体河流表是否命中。
2. 命中则调用具体河流沿线降雨工具。
3. 未命中且名称属于已知九分区河系时，调用河系降雨工具。
4. 两者均不命中时返回可解释的未找到结果，不回退天津滚动预报。

### 4.4 区域综合风险工具

提供区域综合风险查询入口，复用现有区域坐标解析与 `query_region_risk_levels` 能力，并行查询：

- 地质灾害风险；
- 山洪风险；
- 中小河流洪水风险。

工具输出保留每一类风险的数据状态、风险等级、命中数量、隐患点数量和防范建议。回答层只使用工具实际返回的信息。

### 4.5 水库与景区

不新建重复工具。通过现有 `query_decision_weather_for_poi` 完成：

- 于桥水库未来三天降雨；
- 盘山景区未来两天天气。

新增路由和验收测试，确保“水库”“景区”等后缀稳定进入 POI 决策天气工具。多日数据必须逐日展示，注意事项必须经过数据事实门控。

## 5. 错误处理与降级

- 天河失败：返回天河服务暂不可用，不调用本地 LLM 代答。
- 河流未找到：说明未在河流数据库中定位到该河流，不改查天津或整个海河流域。
- 河流数据库失败：说明河道空间数据暂不可用。
- 降雨预报文件失败：说明当前无法获取对应时段的沿河降雨预报。
- 风险接口有效但无命中：输出“无风险”。
- 风险接口失败：输出查询失败，不输出“无风险”或“暂无对应时次风险资料”。
- POI 有歧义时沿用现有 POI 选择策略，不猜测外省同名地点；本次标黄地点应优先命中天津于桥水库和天津盘山景区。

## 6. 兼容性约束

- 不开启或绕过 `ENABLE_FAST_PATHS = False`。
- 不改变 Chainlit 登录、认证、用户权限和消息状态展示。
- 不改变天津滚动预报、既有风险表、POI 决策天气和其他问答的输出格式。
- 不硬编码内网地址、数据库密码或个人环境路径。
- 不修改历史打包目录 `weather-analyzer-mcp-20260206`。
- 新增逻辑优先放入可独立测试的核心模块，避免继续扩大 `chain_gzt.py` 和 `message_orchestrator.py` 的职责。

## 7. 测试与验收

实施采用测试先行：先写失败用例，再做最小实现。

### 7.1 天河目录

- 51 个问题逐题命中天河。
- 标点和空白变体仍可命中。
- 工具参数保留用户原文。
- “未来三天天气怎么样”等非目录问题不命中天河。
- “高温预警期间最高会到多少度”继续命中本地生效预警工具。
- 天河失败时禁止本地代答。

### 7.2 标黄问题

- “明天泃河有雨吗？”命中具体河流沿线降雨工具，使用下一自然日和 5 公里缓冲。
- “今天晚上滦河有雨吗？”动态使用今晚时段，不误走天津滚动预报。
- “今天蓟州可能有哪些风险？”一次返回三类区域风险并正确区分无风险和失败。
- “未来三天于桥水库降雨预报？”命中 POI 决策天气并按三天拆分。
- “盘山景区未来两天天气？”命中 POI 决策天气并按两天拆分。

### 7.3 河流空间与时间

- 使用 `river_table_full` 而非简化河流表。
- 精确匹配优先于包含匹配，同名河段正确合并。
- 5 公里缓冲在米制坐标系中计算。
- 坐标系转换、空几何、无效几何和无像元处理正确。
- 明天、今晚和多日窗口不重叠、不重复累计。

### 7.4 全量回归

- Chainlit 消息编排测试。
- MCP 河网、河系预报、滚动预报和风险测试。
- POI 决策天气和注意事项事实门控测试。
- 快速路径永久关闭测试。
- 现有天河边界和高温预警路由测试。
- 完成后执行代码审查、代码简化审查和最终验证。

外网环境无法访问内网天河和生产数据库时，自动化测试使用模拟响应和合成几何/栅格；部署到内网后按上述 56 个问题（51 个天河问题加 5 个标黄问题）执行真实接口验收。

## 8. 非目标

- 不重写整个 Agent 或消息编排器。
- 不启用快速路径。
- 不因新增 51 题而把其他相似气象知识问法自动扩展到天河；此前已验收的 03/04/05 问法继续兼容。
- 不自行实现天河已经负责的问题答案。
- 不在本次紧急交付中建设通用空间天气查询平台。
